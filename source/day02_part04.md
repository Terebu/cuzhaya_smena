# Codex — «Чужая смена»

## День 2, часть 4 «Диагноз: анахронизм»

Реализуй приложенный постановочный сценарий и сохрани непрерывность со всеми ранее внедрёнными частями.

### 1. Переход из предыдущей части

Часть 3 заканчивается входом Лены Соколовой, Дарьи и Семёна в клубы к Шурику и Электронику.

Поэтому новая часть начинается непосредственно внутри `bg int_clubs_male_day`.

Не добавляй повторного выхода на улицу перед технической сценой.

Шурик и Электроник подготовили стабильный источник питания, но не имеют безопасного способа подключить незнакомый разъём смартфона. Телефон остаётся разряженным, не разбирается и возвращается Лене.

После этого Семён отправляется уточнять время музыкального вечера у Ольги Дмитриевны, а Лена и Дарья идут в медпункт обработать небольшую царапину.

### 2. Медпункт

Используй оригинальные фоны:

- `bg ext_aidpost_day`
- `bg int_aidpost_day`

Используй оригинальный спрайт Виолы с тегом `cs`, предварительно проверив зарегистрированные эмоции и одежду.

Для Дарьи применяй существующие пользовательские PNG из `sp/Dasha sprites/new/`.

Дарья — обычный человек из Москвы 2026 года. Она не получает необычных характеристик, не проходит экспериментального обследования и не имеет фантастической предыстории.

Медицинская сцена должна состоять из обычного осмотра и обработки небольшой царапины Лены.

### 3. Анатомический плакат

В оригинальном медпункте находится необычный анатомический плакат, который поклонники игры связывают с кыштымским Алёшенькой.

Лена замечает сходство и вспоминает историю 1996 года.

Важно:

- Не утверждать, что на плакате достоверно изображён именно Алёшенька.
- Не объявлять сходство доказательством путешествия во времени.
- Не создавать отдельный CG, если изображение уже присутствует в оригинальном фоне.
- Проверить, что нужная часть фона не закрыта спрайтами.
- Виола не обязана знать происхождение плаката.
- Виола относится к догадке Лены со здоровым скепсисом.

Если фактический BG в установленной игре отличается и изображение отсутствует, сообщи об этом. Не добавляй самодельный плакат без отдельного задания.

### 4. Дружеская развилка Виолы

Создать переменные только при отсутствии существующих эквивалентов:

```
default cs_friend_viola = 0
default cs_met_viola = False
default cs_helped_viola_day2 = False
```

Во время знакомства:

```
$ cs_met_viola = True
```

Выбор:

**«Предложить Виоле помощь с материалами»**

```
$ cs_friend_viola += 1
$ cs_helped_viola_day2 = True
```

**«Поблагодарить Виолу и не задерживаться»**

```
$ cs_helped_viola_day2 = False
```

Не начислять очки при возвращении к общему сюжету.

Обе ветви соединяются в сцене 32.

При нуле очков Виола сохраняет нейтральное отношение, а не становится враждебной.

Не создавать отдельную романтическую линию с Виолой.

### 5. Правила спрайтов для этой части

Выполняй глобальные правила показа и скрытия, установленные для всего мода.

**Начало части, внутри клубов:**

- Шурик и Электроник находятся у рабочего стола.
- Дарья и Семён находятся в помещении.
- Смены говорящего не должны автоматически скрывать персонажей.
- При невозможности одновременно показать четырёх героев использовать осмысленное переключение ракурса: например, пара Шурик/Электроник, затем Семён/Дарья.

**Выход из клубов:**

- Скрыть Шурика и Электроника.
- Показать Семёна и Дарью на новом фоне.
- После ухода Семёна к Ольге скрыть только Семёна.
- Дарья остаётся рядом с Леной во время прогулки.

**Вход в медпункт:**

- При `scene bg int_aidpost_day` восстановить Дарью.
- Показать Виолу.
- Не оставлять в помещении спрайты Семёна, Шурика или Электроника.

**Обнаружение плаката:**

- Если необходимо показать изображение на фоне, убрать спрайты, перекрывающие его.
- Когда разговор возвращается к Виоле, восстановить соответствующие спрайты.
- Не менять масштаб Дарьи при каждой реплике.

**Выход из медпункта:**

- Скрыть Виолу.
- После смены фона показать Дарью.
- После возвращения к клубам показать Семёна.
- Оставить Дарью и Семёна видимыми в общем финале части, если они находятся в текущем кадре.

### 6. Изменения последующих частей

Если скрипт использует пользовательские имена изображений, сохраняй действующие теги и трансформации вместо создания конфликтующих дублей.
